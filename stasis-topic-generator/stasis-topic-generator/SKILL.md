# 争点选题引擎

## 它解决什么问题

读者看完只会点头的内容，不会被转发，也不会被记住。这个 skill 在一个话题或一条资讯里找真正值得争论的问题：一件大家公认的事实，加上不同的解读，再加上一个需要读者做出判断的问题。同时检查这个问题和多少类读者真实相关，因为读者只在几秒内判断"这跟我有没有关系"。

找不到好争点，就如实说"这里没有"，不要硬造矛盾。伪争议和夸大的关联一旦被读者识破，消耗的是账号的信任，比一篇平淡的文章代价大得多。

## 默认设定

- **读者**：对 AI 好奇的普通读者，不是从业者。用生活语言，术语第一次出现时用一句话解释。用户说明读者偏从业者或其他人群时，按用户说的调整。
- **平台**：微信公众号长文。
- **目标**：让选题触达尽可能多的、真正相关的读者，适合靠阅读量和转发获益的账号（如流量主）。用户的目标不同（卖货、树立专业形象）时，按用户的目标调整取舍。
- **输入常常是资讯**：资讯只告诉读者"发生了什么"，选题的价值在资讯之上的那个问题。拿到资讯后，先分清"报道说了什么"和"报道没说什么、没证明什么"，争点往往藏在后者里。

## 他人内容只当素材

用户给出别人的文章、视频或资讯时，把它拆成事实、问题、观点三部分，再形成自己的判断，不要改写成同一篇文章的另一个版本。原因：改写练的只是表层表达，观点的来源仍然是别人，读者在别的号也能读到同样的内容。

## 事实核实

AI 领域的模型版本、功能、跑分、价格、发布时间、政策更新极快，记忆里的印象很可能已经过期，而写错的事实会直接毁掉一篇观点文章。

- 有搜索工具时，涉及当前事实先搜索，以官方发布和一手来源为准，再进入选题分析。
- 没有搜索工具，或搜不到可靠来源时，标【待核实】，不当作事实陈述。
- 区分三类说法：已验证的事实、厂商宣称或单方指控（尚未被独立验证）、合理推论（用"可能""往往"表达）。涉及刑事案件时用"涉嫌"，指控不等于定论。demo 效果不等于普通人实际能用到的效果。

## 选择模式

| 用户情况 | 模式 |
|---|---|
| 给出话题或资讯，要选题（默认） | 快速模式 |
| 选定了某个方向，或说"深挖""展开""帮我想清楚" | 深挖模式 |
| 指定某一层，如"只要定义争点" | 单层模式 |

分模式的原因：完整分析很长，每次都跑全流程会让用户先读一大屏才拿到选题。先给精简结果，用户选中后再深挖。

## 快速模式

1. **拆事实**：列出已知事实、观点或单方说法、【待核实】项。分不清事实和观点时，宁可多标一条。
2. **找矛盾，压成核心争点**：这个话题真正冲突的是什么？可从认知冲突（大家以为 A，实际可能是 B）、利益冲突、价值冲突、现实与理想的落差、短期与长期的冲突中找。把矛盾压成一个读者能站队的问题。
3. **四层候选**：Fact / Definition / Nature / Procedure 每层最多 3 个候选，只写争点问题和一句话理由。某层没有真争点就写"本层无"，不凑数。"同一观点换三个标题"只算一个候选。四层的定义和边界见 `references/four-stases.md`，用之前先读。
4. **淘汰**：删掉没有真争点的（只是"介绍一下""分享几个"）、换皮重复的、看完只剩空话结论的、依赖未证实推测才能成立的、标题承诺正文兑现不了的。简要说明淘汰了什么、为什么。
5. **关联度评估**：对留下的候选，评估有哪几类读者会觉得"这跟我有关"，只保留真实的关联。方法见 `references/relevance.md`，用之前先读。
6. **推荐 3 个**，优先选争点强且真实覆盖面广的，按下面模板输出，最后问用户想深挖哪一个。

### 快速模式输出模板

```
## 事实拆解
已知事实 / 观点或单方说法 / 【待核实】

## 核心矛盾与核心争点
（各一两句话）

## 四层候选
Fact：…
Definition：…
Nature：…
Procedure：…

## 淘汰说明
（一两句）

## 推荐选题
### 选题 1：暂定标题
- 争点：一句话
- 所在层级：
- 读者原本怎么想 → 这篇要让他怎么想：
- 主要读者 / 扩展读者 / 关联强度：
- 公众号开头（2-3 句，尽早交代这件事为什么和读者有关）：
- 为什么读者会听进去：
- 标记：【时效选题】或【常青选题】；待核实项
（选题 2、3 同上）
```

## 深挖模式

先读 `references/stress-test.md`、`references/relevance.md` 和 `references/gongzhonghao.md`，然后依次输出：

核心争点 → 把事情搞清楚 → 反方压力测试 → 换一种解释 → 找前人解法 → 认知升级 → 关联度与三种框架 → 现实触发 → 内容延展 → 选题、标题、摘要、开头一起确定 → 最终决策（A 立即写 / B 修改后写 / C 暂缓 / D 放弃）。

深挖是用来给选题"找茬"的。如果反方压力测试后观点站不住，或素材撑不起标题，直接建议放弃或修改，不要为了完成流程硬写下去。

## 单层模式

用户指定某一层时，只围绕那一层出选题，数量按用户要求（默认 5 个）。每个选题输出：标题、该层争点一句话、开头钩子、为什么这个角度让人听得进去。数量多时仍要保证争点互不相同，而不是换标题。

## 四层速查

| 层 | 核心问题 | 判断法 |
|---|---|---|
| Fact 事实 | 这件事是真的吗？为什么会这样？ | 能用证据回答 |
| Definition 定义 | 它到底算什么？ | 能接"它其实是……" |
| Nature 性质 | 好还是坏？该不该？严不严重？ | 删掉价值判断，问题就没意义了 |
| Procedure 程序 | 谁来负责？按什么规则、标准处理？ | 落到责任、规则、决策标准 |

## 底线

- 不编造数据、案例、专家观点、调查、趋势；不把个例包装成普遍现象，不把推测包装成事实。
- 关联必须真实。能用一句具体的话说清"这件事会怎样影响你的钱、时间、工作或决策"，才算关联；说不出来就不硬凑。
- 不为"爆款感"硬造矛盾，不靠"AI 要取代你""不看就晚了"之类贩卖焦虑。AI 领域这类内容泛滥，读者已有免疫力，扎实的判断反而稀缺。
- 观点要"可信的锋利"：有明确立场，但允许聪明的人合理反驳。太弱（"应该理性看待"）没有冲突，太强（"用 X 的人都是……"）一击即溃。
- 争议要来自真实的判断分歧，不挑动对立，不贬低某个群体，不把国籍、身份当作动机。

## 冲突时的优先级

事实真实性 > 真正的争点 > 认知增量 > 反方可辩性 > 关联真实度 > 内容延展性 > 现实触发 > 传播包装 > 标题技巧。前面的原则永远不为后面的牺牲。
